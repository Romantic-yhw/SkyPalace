# 制作天宫奇观视频

## 核心原则

把用户的一句话扩展成可生成、可质检、可继续制作的天宫奇观视频生产包。以“不可能关系＋四级尺度链＋动态揭示”制造奇观，不以堆叠宫殿、瀑布和光效冒充宏大。

## 资源路由

开始创作前按任务读取以下文件；所有引用均为本 Skill 目录的相对路径：

| 任务 | 必读资源 |
| --- | --- |
| 所有任务 | `references/wonder-design.md`、`references/visual-bible.md`、`references/quality-gates.md` |
| 设计分镜 | `references/shot-library.md` |
| 生成关键帧或图片提示词 | `references/image-prompts.md` |
| 生成视频片段或视频提示词 | `references/video-prompts.md` |
| 需要完整成品范例 | `references/examples.md` |

不得只读取示例后仿写；示例不能替代奇观设计、图片、视频和质量规范。

## 一句话工作流

1. 从用户的一句话提取主题、核心奇观、人物、情绪、时间、天气、时长、画幅与交付深度。非关键缺项采用默认值：六镜头、30 秒、16:9、电影级超写实东方神话、两位背向镜头且高度仅占画面 0.25%–0.8% 的极小同行者。
2. 仅在付费调用、必需参考图缺失、输入互相冲突或涉及受保护 IP 复刻时提问。其余推断写入 `brief.json`，不要用连续追问打断创作。
3. 需要落盘时运行 `scripts/init_project.py` 创建项目；不得覆盖已有非空目录。
4. 写 `world-bible.md`，锁定原创建筑家族、材料、人物、服饰、色彩、光向和空间连续性。
5. 设计 4–8 镜头，默认六镜头。每镜只保留一个主奇观、最多两个辅助奇观，并让“召唤→仰望→进入→穿越→反转→抵达”的认知规模持续升级。
6. 为每镜写一个完整图片提示词。明确核心奇观、前中远极远四层空间、建筑受力、人物行动、机位焦段、45%–65% 巨构占比、巨构出框、28%–42%有效留白、22%–32%行动区、光色材质和失败规避；人物高度默认只有画面 0.25%–0.8%，优先 0.3%–0.6%，人物必须小于门钉或桥栏局部，人物前方仍有至少画面宽度 30% 的无遮挡连续路径。除非用户明确要求人物近景，人物超过画面 1% 必须重做。
7. 逐张独立生成关键帧并质检。不得用多格拼图替代独立关键帧，不得用历史图替代失败结果。只重做失败镜头。
8. 以通过的关键帧为首帧，为每镜写一个完整、无空行的单段视频提示词，将摄影机轨迹、人物动作、分层环境运动、视差、揭示节拍、结束状态、连续性和防漂移要求合并在同一段中；不要拆出独立否定词。
9. 逐镜生成视频并质检。巨构保持结构稳定，主要运动来自摄影机、云、水、光、衣袂和白鸟。
10. 运行 `scripts/validate_package.py <项目目录>`，修复所有阻塞错误后再交付。

## 工具与费用门禁

- 先检查当前环境实际可用的生图、图生视频、浏览器和剪辑能力，不假设某一供应商存在。
- 任何可能产生费用的图片或视频生成调用前，列出模型、次数、预计产物和已知成本边界，等待用户明确确认。
- 用户确认后只执行确认范围内的调用；增加镜头、重试或切换付费模型需要再次确认。
- 仅浏览器可用时使用用户真实登录态；出现验证码、强制登录、账号风险或平台警告立即停止。
- 无生成工具时完整输出简报、世界观、分镜、图片提示词和视频提示词，状态停在 `video_prompts_ready`，不得声称已经生成媒体。
- 不自动发布到任何外部平台。

## 状态与交付

维护 `status.json`，阶段只使用：`briefed`、`storyboard_ready`、`image_prompts_ready`、`images_ready`、`video_prompts_ready`、`clips_ready`、`ready_for_edit`、`complete`、`blocked`。

交付时列出生成模式、项目路径、镜头数、尺寸与时长、已通过和失败的质量门禁、付费调用事实、未验证项以及下一步。生成失败时保留已通过产物和失败原因，不从头重做整个项目。

## 快速调用

```text
使用 $make-sky-palace-video，把“巨月打开天门，两位旧友沿倒流天河赴九重天宫旧约”做成30秒横屏天宫奇观视频。
```

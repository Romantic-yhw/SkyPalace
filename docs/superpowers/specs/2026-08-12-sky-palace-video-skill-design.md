# SkyPalace 天宫奇观视频 Skill 设计规格

## 1. 目标

创建一个名为 `make-sky-palace-video` 的 Codex Skill。用户只需提供一句中文自然语言，例如：

> 用黄昏、倒悬天河和两位同行者，生成一支 30 秒的九重天宫朝圣视频。

Skill 即可将其展开为可执行的天宫奇观视频生产方案，包括创作简报、世界观连续性规则、分镜、逐镜图片提示词、逐镜视频提示词、生成执行、质量检查和交付清单。

Skill 采用混合执行模式：存在可用生图或图生视频工具时执行生成；缺少工具时输出同等完整度的生产包。任何可能产生费用的外部生成调用都必须先获得用户确认。

## 2. 产品边界

### 2.1 包含

- 根据一句话推导主题、情绪、奇观母题、人物关系、时间、天气、时长和画幅。
- 在信息不影响安全、费用或核心叙事时采用明确默认值，避免连续追问。
- 设计 4–8 个相互递进的镜头，默认 6 镜头、总时长 30 秒、横向 16:9。
- 为每个镜头生成可直接复制的精细图片提示词。
- 为每个镜头生成单段式、可直接复制的图生视频提示词。
- 保持建筑语言、人物外观、服饰、色彩、光照方向和空间关系连续。
- 支持“只输出提示词”“生成关键帧”“生成视频片段”“完整生产包”四种交付深度。
- 对图片与视频提示词执行结构、奇观强度、空间、连续性和可生成性检查。
- 生成结构化项目目录和状态文件，保存输入、决策、提示词、产物与质检结果。

### 2.2 不包含

- 不内置、转存或记录账号 Cookie、API Key、登录态与个人信息。
- 不绕过验证码、平台风控、付费确认或服务条款。
- 不承诺任何单一模型一定生成完全一致的建筑、人物或动作。
- 不自动发布到抖音、小红书、YouTube 等外部平台。
- 不把剪辑器、云端生成平台或某个模型写成唯一依赖。

## 3. 用户体验

### 3.1 一句话调用

推荐入口：

```text
使用 $make-sky-palace-video，把“巨月打开天门，两位旧友穿过倒流天河赴九重天宫之约”做成 30 秒横屏天宫奇观视频。
```

缺失参数采用以下默认值：

| 参数 | 默认值 |
| --- | --- |
| 镜头数 | 6 |
| 总时长 | 30 秒 |
| 单镜头 | 4–6 秒 |
| 画幅 | 16:9 |
| 视觉基调 | 超写实东方神话史诗 |
| 时代语言 | 盛唐建筑语汇，不复刻具体文物 |
| 人物 | 两位背向镜头的同行者 |
| 输出语言 | 中文提示词，保留必要英文视觉关键词 |
| 生成深度 | 有工具则先展示方案并在付费调用前确认；无工具则输出完整生产包 |

只有以下情况需要追问：

- 用户要求的总时长、画幅或人物数量互相冲突。
- 需要付费调用但用户尚未授权。
- 必需参考图缺失。
- 用户明确要求复刻具体作品、人物或受保护 IP，需先调整为原创视觉语言。

### 3.2 交付结构

每次任务输出：

```text
sky-palace-project/
├── brief.json
├── world-bible.md
├── storyboard.md
├── prompts/
│   ├── image/
│   └── video/
├── images/
├── clips/
├── qa-report.json
└── status.json
```

图片或视频尚未生成时保留目录和状态，但不得用历史素材冒充本次产物。

## 4. 奇观设计系统

### 4.1 奇观不是“堆元素”

每个镜头只设置一个主奇观和最多两个辅助奇观。主奇观必须满足至少三项：

1. **不可能关系**：天河倒流、宫阙穿月、瀑布落入星海、山岳悬于云上等现实中不成立的空间或物理关系。
2. **多级尺度链**：人物、栏杆或白鸟、宫门或巨柱、山岳或浮空大陆、月轮或天体至少四级参照。
3. **画框无法容纳**：核心巨构至少一个边缘主动出框，暗示画外仍在延伸。
4. **深度穿透**：前景遮挡、中景行动路径、远景终点与极远天体共同构成四层空间。
5. **动态揭示**：镜头运动逐步暴露规模，而不是开场就平铺全部信息。

### 4.2 构图硬指标

- 核心巨构视觉占比通常为 45%–65%，但至少一侧或顶部超出画框。
- 天空、云海、镜面或远山形成 28%–42% 的有效留白；留白中允许少量光束、白鸟和空气层次，禁止成为纯白雾墙。
- 人物行动区占画面下方约 22%–32%，人物前方保留至少画面宽度 30% 的连续无遮挡路径。
- 人物高度通常只有画面高度 0.25%–0.8%，关键巨物镜头优先 0.3%–0.6%，并且小于门钉、栏杆局部或柱身铆钉；除非用户明确要求近景，人物超过 1% 即失败。无人物镜头必须使用白鸟、建筑窗格、瀑布或山峰建立尺度。
- 近景巨构使用 14–22mm 广角、低机位、局部裁切与遮挡强化压迫感；远景奇观使用长距离空气透视和多层云海强化不可抵达感。
- 不把宫殿、浮岛、瀑布和光效平均铺满背景。

### 4.3 六镜头默认奇观曲线

| 镜头 | 叙事作用 | 奇观策略 | 默认运动 |
| --- | --- | --- | --- |
| 1 | 召唤 | 遮挡后首次看见天门或巨月 | 缓慢前移并轻微抬头 |
| 2 | 仰望 | 大陆级天宫或倒悬天河压入画框 | 低机位横移揭示规模 |
| 3 | 进入 | 镜面天庭、通天神廊或无边阶梯 | 沿行动轴稳定推进 |
| 4 | 穿越 | 云海天路、浮空山峡或天河内部 | 侧后方跟随并产生视差 |
| 5 | 反转 | 更高一层天体级奇观出现 | 越过前景遮挡后大幅揭示 |
| 6 | 抵达 | 门后仍有第二重更辽阔世界 | 缓慢升高，保留未完成感 |

镜头之间的规模必须递增或认知反转，不允许六张图只是更换宫殿背景。

## 5. 图片提示词设计

每条图片提示词写成一个完整段落，按下列顺序自然合并，不输出字段标签：

1. 输出约束：单张图片、画幅、无解释与无文字。
2. 类型与真实度：东方神话、电影摄影、超写实、非游戏概念图。
3. 主奇观：名称、不可能关系、绝对尺度、出框方式。
4. 空间结构：前景遮挡、中景人物路径、远景终点、极远天体。
5. 建筑结构：台基、柱、斗拱、重檐、石材和受力关系。
6. 人物连续性：人数、服饰、发型、朝向、动作与画面占比。
7. 摄影参数：机位高度、焦段、俯仰角、透视、景深。
8. 构图指标：巨构、留白、行动区和尺度参照。
9. 光线与空气：时间、主光方向、体积光、云层与雾层。
10. 色彩与材质：主色、点睛色、玉石、木材、金属、水体。
11. 失败规避：把拥挤、景区感、塑料 CG、错误透视、变形、文字和水印自然合并在段尾。

提示词必须给出可观察、可判断的画面关系，避免只写“震撼、仙气、史诗、8K”等抽象形容词。

## 6. 视频提示词设计

每个镜头只输出一个连续段落，不拆分“正向提示词”“负面提示词”或参数清单。段落必须包含：

- 首帧中哪些物体必须保持不变。
- 摄影机起点、方向、速度、轨迹、俯仰与结束位置。
- 人物的步伐、停顿、回望或抬头动作，且动作幅度与远景人物尺寸匹配。
- 衣袂、发丝、浅水、云海、瀑布、白鸟、光尘的分层运动速度。
- 前景、中景、远景的视差关系。
- 主奇观的揭示时点和镜头情绪峰值。
- 建筑、月轮、门体、桥面和人物身份的连续性。
- 对漂移、呼吸变形、凭空增物、镜头抖动、人物滑行、错误水流和过曝的规避要求。

默认使用低到中等运动强度。巨构本体保持稳定，让云、水、光、衣袂和摄影机共同产生生命感；禁止让宫殿像软体一样呼吸或让整座浮岛无意义晃动。

## 7. Skill 架构

```text
skills/make-sky-palace-video/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── references/
│   ├── visual-bible.md
│   ├── wonder-design.md
│   ├── image-prompts.md
│   ├── video-prompts.md
│   ├── shot-library.md
│   ├── quality-gates.md
│   └── examples.md
└── scripts/
    ├── init_project.py
    └── validate_package.py
```

仓库根目录另包含：

- `README.md`：仓库定位、安装、调用方式、参数、例子、工具兼容、费用与发布边界。
- `tests/`：脚本测试、合法包夹具、失败包夹具和三类 Skill 使用场景。
- `docs/superpowers/specs/`：设计规格。
- `docs/superpowers/plans/`：实施计划。

`SKILL.md` 只保存执行流程、必读资源路由和不可跳过的门禁。精细视觉知识与长提示词规范放入 `references/`，避免每次调用加载无关内容。

## 8. 执行流程与状态

1. 解析一句话，生成 `brief.json`。
2. 根据目标时长和叙事生成镜头表与奇观曲线。
3. 写入 `world-bible.md`，锁定建筑、人物、色彩和光照方向。
4. 生成逐镜图片提示词并运行静态校验。
5. 若需要生图且工具可用，展示预计次数并在付费调用前确认。
6. 独立生成关键帧，禁止用包含多格画面的拼图替代。
7. 检查奇观强度、构图、人物路径、变形与镜间连续性；失败镜头只重做该镜头。
8. 基于已通过的关键帧生成逐镜视频提示词。
9. 若需要生成视频，重复费用确认、逐镜生成与质量检查。
10. 输出剪辑顺序、建议转场、声音设计和最终状态。

`status.json` 使用以下阶段：

```text
briefed → storyboard_ready → image_prompts_ready → images_ready →
video_prompts_ready → clips_ready → ready_for_edit → complete
```

发生阻塞时记录 `blocked`、失败镜头、失败原因、已完成产物和下一步人工动作。

## 9. 工具适配与降级

- **生图工具可用**：按照逐镜提示词逐张生成；每张完成后检查尺寸、内容和连续性。
- **图生视频工具可用**：为每张通过的关键帧生成独立片段；不把六镜头压进一次生成。
- **仅浏览器可用**：使用用户真实登录态，遇到验证、风控或账号异常立即停止。
- **无生成工具**：交付 `brief.json`、世界观、分镜、完整提示词和工具参数建议，状态停在 `video_prompts_ready`。
- **供应商参数差异**：核心提示词保持供应商无关；模型专用参数只写入执行记录，不污染视觉语义。

## 10. 错误处理

- 输入过短：使用默认值补全，并在简报中明确标记推断项。
- 风格冲突：优先满足用户明确指定的主体与情绪，再保持东方建筑结构和真实摄影逻辑。
- 奇观不足：增加不可能关系、尺度链、画框裁切或动态揭示，不通过堆叠更多宫殿解决。
- 画面过满：删除辅助浮岛、瀑布和装饰，恢复有效天空、云海或镜面留白。
- 人物无路可走：重构中景，保证连续地面或桥面真实通向终点。
- 连续性失败：只重做失败镜头，并引用锁定的世界观与相邻通过帧。
- 付费工具不可用：不伪造生成结果，降级为完整提示词生产包。

## 11. 验证策略

### 11.1 RED 基线

使用此前已生成的六组 V3 提示词作为基线。用户的真实反馈为“奇观感还是差了一些”。基线问题记录为：

- 建筑虽然巨大，但“不可能关系”不足。
- 尺度主要靠形容词和百分比，没有稳定的四级尺度链。
- 六个镜头的视觉升级有限，缺乏认知反转。
- 图片提示词较精细，但视频运动尚未形成同等级规范。

### 11.2 GREEN 场景

至少验证以下三类输入：

1. `巨月打开天门，两位同行者去赴九重天宫旧约，30秒横屏。`
2. `没有人物，拍一座被倒悬天河环绕、从星海升起的东方天宫。`
3. `竖屏15秒，暴雨散去后，一位女剑客穿过云海神廊看见天宫大陆。`

每个输出必须通过：

- 必需文件与 JSON Schema 结构检查。
- 每镜一个主奇观、最多两个辅助奇观。
- 至少一个不可能关系和四级尺度链。
- 图片提示词必需维度检查。
- 视频提示词单段结构和必需运动维度检查。
- 人物、建筑、光线和色彩连续性检查。
- 费用确认和工具降级行为检查。

### 11.3 脚本测试

- `init_project.py` 在临时目录创建完整结构，不覆盖已有项目。
- `validate_package.py` 对合法夹具返回 0，对缺少提示词、镜头重复、无尺度链、无连续路径和视频提示词分段等失败夹具返回非零。
- 运行系统 Skill 校验器检查 frontmatter、目录命名和 `agents/openai.yaml`。
- 运行 `git diff --check`，确保不存在空白错误。

## 12. 成功标准

- 用户能用一句中文触发完整工作流。
- 仓库说明足以让新用户安装并完成第一次调用。
- Skill 不依赖单一供应商，工具缺失时可完整降级。
- 所有图片提示词具备可观察的奇观关系、尺度链、空间、人物、摄影、光色、材质和失败规避。
- 所有视频提示词为完整单段，包含摄影机、人物、环境、视差、节奏、连续性与防漂移要求。
- 三类使用场景通过，脚本和 Skill 静态校验通过。
- 本地提交推送至 `https://github.com/renmu2017/SkyPalace.git`，并通过远端提交哈希核验。
